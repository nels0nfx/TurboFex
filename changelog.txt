TurboFex v1.3.5 - plugins (first stage): extra commands from other developers, running in a sealed sandbox
CHANGED IN 1.3.5
- NEW: PLUGINS. A plugin is a small folder (a `turbofex-plugin.json` and one JavaScript file) that adds commands. It runs in a sealed sandbox (QuickJS in WebAssembly, one worker thread per plugin): it cannot see files, passwords, the network, the bot's memory or other plugins. It can only ask the bot for a few things, and the bot checks each one against what the plugin declared and what the owner allowed.
- OFF until the owner turns it on: `plugin on`. Nothing is loaded, created or changed while plugins are off. `plugin off` removes every plugin command at once. Owner only.
- INSTALL: copy the plugin folder into `data/plugins/`, then `plugin list`, `plugin install <name>` (shows in plain words what it asks for and gives a 4-letter code), `plugin confirm <code>`. Also `plugin enable|disable|remove <name>`, `plugin info <name>`, `plugin log <name>`. If a plugin's files change after it was installed, it does not start until it is installed again.
- PER GROUP: inside a group, `plugin groups <name> allow|deny|only|all`. A plugin that is not allowed in a group gets no answer there.
- Permissions in this first stage: send messages in the chat where the command was used, its own saved notes, listed internet domains (https only, public addresses only), group name and member counts, a timer, a short note to the owner. Plugins never get real phone numbers or chat ids.
- SAFETY: an endless loop, a memory bomb or a plugin that takes too long is stopped; a plugin that keeps failing or breaks the rules is switched off and the owner is told. A memory guard (default 96 MB per call) and the number of plugins awake at once (default 8) can be changed: `plugin set guard 96`, `plugin set max 8` (0 = no limit). Before plugins start, the bot runs a safety check on the server; if it fails, plugins stay off and the rest of the bot works as before.
- Needs Node.js 22 or newer and the `quickjs-emscripten` package (installed as an optional package). On Node 20 or without the package, plugins stay off and TurboFex works as usual.
- New menu category PLUGINS (shown only when plugins are installed). Not in this stage: events, pictures and files, group management by plugins, a store.

TurboFex v1.3.3 - several accounts on one server, more hosts, Termux prefix fixed
CHANGED IN 1.3.3
- NEW: SEVERAL ACCOUNTS. Run more than one WhatsApp number from the same folder. Each account is its own bot process with its own login, settings and data, so they cannot overwrite each other. Turn it on with a file `accounts.json` (copy `accounts.example.json`) or the variable `ACCOUNTS=main,shop`. The account called `main` keeps the old places (`data/`, `session/`, `session_id.txt`) so a running bot is not linked again; every other account has `accounts/<name>/` with its own `session_id.txt`. Per account: `prefix`, `timezone`, `number`, `sessionId` (or the variable `SESSION_ID_<NAME>`), `enabled`. Log lines start with `[name]`. One account crashing does not stop the others. - NEW: MORE HOSTS. A `Dockerfile`, `docker-compose.yml`, `.dockerignore`, a pm2 file (`ecosystem.config.js`), a systemd service (`hosting/turbofex.service`) and a `Procfile`. When the host gives a `PORT` (Render, Railway, Koyeb, Heroku and similar) the bot opens a tiny status page that only says it is running, so the host does not stop it. Without PORT nothing is opened.
- NEW: README "Hosting guides" (Termux, VPS, Docker, panels, web-service hosts, Windows and Mac) and "Several accounts on the same server".
- FIXED, Termux: Termux has its own variable called PREFIX (a folder path). The bot used it as the command symbol, so commands did not work on a fresh Termux install and `PREFIX=` in config.env was ignored. The bot now ignores a PREFIX that is not a short symbol. `BOT_PREFIX` also sets the symbol, and on Termux a `PREFIX=` line in config.env is used as BOT_PREFIX.
- `accounts/` and `accounts.json` are never touched or published by the updater, the clean-up or the release check.

TurboFex v1.2.4 - the repeated "Finished syncing with WhatsApp on Google Chrome (Ubuntu)" notice
CHANGED IN 1.2.4
- FIXED: the phone showed "Finished syncing with WhatsApp on Google Chrome (Ubuntu)" again and again on a number with many groups and contacts. Cause (found in the library's own bug reports, WhiskeySockets/Baileys issue 2591, and in the library code): every time a linked device asks the phone to send a message again ("placeholder resend"), WhatsApp shows that notice on the phone. TurboFex v1.2.3 - much faster on accounts with a huge contact list and huge groups
CHANGED IN 1.2.3
- FIXED: slow answers and freezes on big accounts. The bot looked people up by walking through its whole table of known people (and through the whole member list of a group) again and again: for every message, every reply to a private chat, every contact and every tagged person. With thousands of contacts that is millions of steps, and it happened all at once when WhatsApp handed over the contact list after every (re)connect, so the bot froze for seconds, missed WhatsApp's sign of life, reconnected, and froze again. Lookups are now instant (a reverse table in `idmap`, a lookup table for tags in `mentions`, a counter instead of counting all names in `names`).
- CHANGED: the table of known people holds up to 50,000 pairs (was 5,000) and the table of names up to 40,000 (was 6,000), so a big contact list no longer pushes people out and back in all the time.
- CHANGED: big saved files are written and checked less often. A file that takes 300 ms to save is written at most every 6 seconds, and the 10-second safety check of a big file waits 50 times as long as the check itself took. Saving on stop or restart is unchanged.
