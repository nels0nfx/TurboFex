TurboFex v0.2.4 - instant status view, status like

TurboFex v0.2.3 - status, "Waiting for this message", play and view-once
FIXED
- "Waiting for this message" in your private chat: notifications (copies, restart/update messages) were sent to your phone number, which many phones cannot open. They now go to you the way WhatsApp itself addresses you, and every private message to a known person uses that form
- Reconnects every ~50 minutes: WhatsApp's new "status" notices were never acknowledged, so WhatsApp cut the connection. They are acknowledged now (this also explains repeated "Finished syncing" notices and the bot "sleeping")
- Status like: the WhatsApp library has a known bug where likes on statuses are refused by WhatsApp while looking successful. The bot now reads WhatsApp's answer and, when refused, sends the like straight to the poster instead. "statusinfo" shows how many were refused and which route works
- Status speed: statuses are handled 3 at a time (after a reconnect dozens arrive together), expired ones are skipped, and statusinfo shows how long WhatsApp took to bring the last status to the bot
- Group speed: the list of who has which devices is now remembered for 30 minutes instead of 5, so the first message to a group after a quiet period no longer waits for WhatsApp
- play: if YouTube blocks the server, the same song is looked up on SoundCloud and Audius. New "ytcookies" command saves a cookies.txt so YouTube works again
NEW
- relink android: one command logs the bot out and restarts it with the identity that can receive view-once files (you link it again once). The "no content" notice is now sent at most every 6 hours
TurboFex v0.2.2 - status, anti-edit and play
FIXED
- Auto like status: back to the recipient list that worked before, and the like no longer waits behind the view. View and like now start together (the real "viewed" receipt goes first), so statuses are viewed and liked in about a second instead of several
- Anti-edit: edit notices are no longer dropped as "already seen", and every shape WhatsApp uses for edits is understood. The console now logs each edit event it receives and "status" shows how many arrived
CHANGED

It uses the free yt-dlp tool, which the bot downloads once by itself the first time play is used and keeps up to date. Limits: 60 MB / 60 minutes (PLAY_MAX_MB, PLAY_MAX_SECONDS). If the downloader fails, a song name falls back to free music from Audius

TurboFex v0.2.0 - speed, private-by-default, new menu, reactions, server protection

NEW

TurboFex v0.1.8 - fixes for slowness, "Waiting for this message", status, watchers and play
FIXED
- "Waiting for this message": the bot now keeps what it sent so WhatsApp can ask for it again (it was missing). The timing overrides added in v0.1.7 that could make connections and sends fail were removed
- Slow sending (group replies took ~27 s): encryption keys are now kept in memory instead of being read from the disk every time
- Missed commands: a command never waits behind another command (or a long job) in the same chat any more. Only game answers stay in order
- Anti-delete: the copy is now a REPLY to the original message in its chat, names who sent it AND who deleted it (the admin or the sender), and also catches deletions that WhatsApp reports as updates. Never shown twice
- Anti-edit: now also catches edits that WhatsApp reports as message updates or as wrapped messages, and replies to the original
- Auto view-once: when WhatsApp refuses the download you are told why instead of silence
- Status auto view/like/save: counters and a fallback way of marking a status as seen; the status owner is added to the like list in both id forms. !statusinfo shows what arrived and any problem
- .block: phone numbers behind hidden ids are learned from messages, contacts and your groups (kept on disk), so blocking in a private chat now has the number. More request shapes are tried and the reply lists exactly what was tried
- play: a song name now sends REAL AUDIO when it is on Audius (free music by independent artists); otherwise it shows YouTube links and says why
- Auto repair of "Bad MAC" runs at most every 3 hours (each repair makes the next sends slower while WhatsApp sets up new keys)
